# الخادم الداخلي — نظام المواعيد

خادم Node.js **بدون أي مكتبات خارجية**، يشغّل نفس الصفحات ويحفظ البيانات في ملف JSON
داخل الشبكة الداخلية، ويعمل بالتوازي مع Firebase (الوضع المزدوج).

## التشغيل

```bash
node server/server.js
```

عند الإقلاع يطبع الخادم روابطه على الشبكة، مثال:

```
 http://192.168.1.20:8080/
```

وزّع هذا الرابط على الإدارات — كل موظف يدخل بحسابه ويرى مواعيد إدارته،
والمدير العام/مدير النظام يرى كل الإدارات. البيانات مشتركة وتظهر لحظياً على كل الأجهزة.
الجلسات محفوظة: إعادة تشغيل الخادم لا تُخرج المستخدمين.

متغيرات اختيارية:

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `8080` | منفذ الخادم |
| `HOST` | `0.0.0.0` | العنوان الذي يستمع عليه |
| `DATA_DIR` | `server/data` | مجلد البيانات (db.json) |
| `ADMIN_EMAIL` | `admin@local` | بريد مدير النظام الأول |
| `ADMIN_PASSWORD` | `Admin@12345` | كلمة مرور مدير النظام الأول |
| `SYNC_INTERVAL_MINUTES` | `5` | دورية المزامنة مع Firebase |
| `SYNC_DEBOUNCE_SECONDS` | `20` | مهلة المزامنة بعد كل تغيير |
| `SYNC_PULL` | `false` | `true` لسحب المواعيد من السحابة أيضاً |
| `FIREBASE_SA` | `server/service-account.json` | مسار ملف حساب الخدمة |

> عند أول تشغيل يُنشأ حساب مدير النظام تلقائياً. **غيّر كلمة المرور فوراً.**

## كيف يعمل الوضع المزدوج؟
لتثبيت الوضع نهائياً، عدّل سطراً واحداً في أعلى `js/local-backend.js`:

```js
window.APP_MODE = "local";     // الشبكة الداخلية دائماً
window.APP_MODE = "firebase";  // Firebase دائماً
window.APP_MODE = "auto";      // الافتراضي: يكتشف تلقائياً
```

- عند فتح أي صفحة، يفحص النظام وجود `/api/health` على نفس الخادم.
- وُجد → **وضع محلي**: كل البيانات من الخادم الداخلي، تحديث لحظي عبر SSE، وشارة «وضع محلي».
- لم يوجد → **وضع Firebase** كما هو (العمل خارج الشبكة الداخلية).
- للتحويل اليدوي: أضف `?mode=firebase` أو `?mode=local` إلى رابط الصفحة (يُحفظ في المتصفح).

## المزامنة التلقائية مع Firebase (الخيار المعتمد)

ضع ملف `service-account.json` في مجلد `server` ثم شغّل الخادم — **لا تحتاج أي أمر آخر**:

- مزامنة تلقائية كل **5 دقائق** (`SYNC_INTERVAL_MINUTES`).
- مزامنة فورية بعد **20 ثانية** من أي إضافة/تعديل/حذف موعد (`SYNC_DEBOUNCE_SECONDS`).
- مزامنة عند إقلاع الخادم بعد 15 ثانية.
- إذا انقطع الإنترنت: تُسجَّل المحاولة الفاشلة في `server/data/sync.log` وتُعاد تلقائياً في الدورة التالية، ولا يؤثر ذلك على عمل النظام.
- لا تُحذف أي بيانات من السحابة، والترجيح لأحدث `updatedAt`.
- السحب من السحابة اختياري: `SYNC_PULL=true`.

حالة المزامنة تظهر في صفحة **فاحص النظام** ← «المزامنة مع Firebase»، مع زر «مزامنة الآن».

### مزامنة الحسابات
- عند إنشاء مستخدم من الوضع المحلي، يحاول الخادم إنشاء **نفس الحساب في Firebase Authentication**
  بنفس البريد وكلمة المرور، ويكتب مستند `users/{uid}` في Firestore — فيعمل المستخدم خارج الشبكة بنفس البيانات.
- المزامنة الدورية تطابق الحسابات المحلية مع حسابات Firebase بالبريد، وتُبلغك بمن ليس له حساب سحابي.
- إذا لم يكن الإنترنت متاحاً لحظة إنشاء الحساب، يبقى الحساب المحلي يعمل، ويظهر في فاحص النظام
  ضمن «بلا حساب Firebase» لتنشئه من لوحة Firebase.
- كلمة مرور مستخدم محلي: «إدارة المستخدمين» ← «إعادة كلمة المرور» (مدير النظام).

### أوامر يدوية (اختيارية)
عند توفر الإنترنت على جهاز الخادم:

```bash
node server/sync-firebase.js status   # مقارنة فقط
node server/sync-firebase.js push     # المحلي ← Firebase
node server/sync-firebase.js pull     # Firebase ← المحلي
```

حمّل ملف `service-account.json` من Firebase ← Project settings ← Service accounts
واحفظه في `server/service-account.json` (مستثنى من Git).
قاعدة الترجيح: أحدث `updatedAt` يفوز، ولا تُحذف أي بيانات من السحابة.

## النسخ الاحتياطي (تلقائي)
- نسخة عند كل تشغيل + نسخة يومية، تُحفظ في `server/data/backups/` (يُحتفظ بآخر 14 نسخة).
- من فاحص النظام (مدير النظام): **تنزيل نسخة** أو **إنشاء نسخة الآن**.
- الاستعادة: أوقف الخادم، استبدل `server/data/db.json` بالنسخة المطلوبة، ثم شغّله.
- كل البيانات في ملف واحد — احتفظ بنسخ خارج الخادم دورياً (قرص/مجلد شبكي).

## التشغيل التلقائي على ويندوز
1. شغّل `server/start-windows.bat` مرة للتأكد من نجاح الإقلاع.
2. Task Scheduler ← Create Task ← Triggers: **At startup**.
3. Actions ← Start a program ← المسار الكامل لـ `node.exe`، و Argument: `server\server.js`،
   و Start in: مجلد المشروع.
4. Settings ← أوقف "Stop the task if it runs longer than…" ليبقى الخادم يعمل دائماً.

## حماية الدخول
بعد **10 محاولات خاطئة** من نفس الجهاز يُحجب الدخول **5 دقائق** (`LOGIN_MAX_FAILS` / `LOGIN_BLOCK_MINUTES`)،
والحجز العام لا يتأثر.
